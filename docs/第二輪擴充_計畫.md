# 第二輪擴充計畫：Web 應用、report 分類、六項工具改善

> 這是**執行前**擬定的計畫（設計與範圍決策）。實際做了什麼、驗證結果見
> [第二輪擴充_改動紀錄.md](第二輪擴充_改動紀錄.md)。

## 背景與動機

上一輪做了 CI 修復、lineage 靜默吞錯修復、`ingest-reference` skill、解耦式
`frontend/` report viewer。這個治理工具當時只有 CLI ＋ 靜態 report viewer，操作門檻高，
且有幾個維運痛點：新增 domain 容易漏子目錄、改規則不知道會不會炸正式區、顧問區格式
散落多處。本輪把它往「可操作、可視覺化、可模擬」補強，同時**不犧牲**最核心的保證：
閘門區確定性、規則不可繞過人審、正式區不可捏造晉升、樣本與語意描述不可由工具代填。

## 關鍵範圍決策（執行前確認）

1. **Web 應用採本機小型 web server**：純標準庫 `http.server`，不引入 Flask/FastAPI
   等框架，in-process 呼叫既有的 `dataval.engine.validate()`；CLI 完全不受影響。
2. **「套用修正」只把 fix 文字插入前端 DDL 編輯框**，不寫檔、不自動修正——使用者
   確認／修改後仍要重新驗證，避免機械修正產生「語意錯但看似合規」的結果。
3. **規則影響模擬做成獨立指令**，需要時手動跑，不整合進 `rules.py adopt` 自動流程。
4. **允許分段執行、按順序完成**；每一段完成時必須是「可獨立運作」的完整功能，
   不留半成品。

## 探勘確認的關鍵事實（供實作引用）

- report 路徑重構機械可行：`run.py` 建三式報告路徑發生在讀 `meta["domains_loaded"]`
  之前，只要把讀 domains 的時機提前即可分類。`merge_advisory.py`、`promote.py`、
  `architecture_test.py` 各自假設扁平路徑，需一併改。
- report diff 有現成樣板可抄：`rules_history.py` 的 `diff_rules` 用 id 當 key 逐欄位
  比對；report diff 照同結構、改用 `(check_id, target)` 當 key。
- `prodgraph.load_subjects()` 是公開函式，已會完整解析正式區 subject，影響模擬與全域
  lineage 圖都應重用它。
- 正式區不存樣本，任何「重跑正式區規則」的模擬天生無法檢驗樣本相依規則——必須誠實揭露。
- 一個真實 bug：`advisory_export.py` 的 prompt 寫著 `config/advisory_result.schema.json`，
  實際檔在 `config/_engine/`；且該 schema 檔從未被程式讀取（真正驗證是手寫函式），
  是「兩份會漂移的權威來源」。

## 執行順序與各項設計

- **0. Advisory prompt 路徑 bug**：修正路徑、把手寫驗證規則逐條內嵌進 prompt（讓
  agent 讀生成檔就自足）、在驗證函式上方標註三處耦合。
- **1. 共用 report 路徑輔助 + 分類**：新增 `dataval/report_paths.py`
  （`primary_domain` / `report_dir_for` / `find_report_json`）；報告分類到
  `reports/<域>/`；precheck.md 例外維持扁平；相容舊扁平路徑。
- **2. Domain 腳手架**：`rules.py new-domain <NAME>` 建符合 `domains_layout_test`
  契約的資料夾骨架（knowhow/naming/erd/flows/ssot），不含規則、不覆蓋既有。
- **3. 單一 DDL 產四件套骨架**：`scaffold_input.py <名> <ddl>` 依型別產佔位樣本、
  FK→候選 relations、context 佔位；終端明確警告三者都須人工替換。
- **4. Report diff**：`report.py::diff_findings` ＋ `report_diff.py` CLI。
- **5. 規則變更的正式區影響模擬**：`simulate_impact.py`，重用 `load_subjects`，
  靠「晉升時零 fail」不變量偵測退化；揭露樣本限制；純只讀。
- **6. Lineage 視覺化**：(a) 前端「Lineage」分頁畫單一 subject 關聯圖（零新後端、
  零依賴 inline SVG）；(b) `prodgraph.export_graph` ＋ web app 路由畫全域圖。
- **7. 顧問區文件整併**：`AGENTS.md` 註明格式以生成 prompt 為準、不必另查 schema。
- **8. 本機 Web 應用**：`webapp.py`（`http.server`），路由 `/`、`/api/subjects`、
  `/api/validate`（寫入 input/ 後 in-process 驗證）、`/api/lineage-graph`；前端加
  「送驗」分頁與「套用修正」按鈕；離線仍可用「載入既有報告」。
- **9. 持續 brainstorm**：把發現但不該做／低優先的項目記進 `IMPROVEMENT_BACKLOG.md`。

## 不可破壞的保證（貫穿全程）

1. 閘門只用確定性規則；LLM 只進顧問區。
2. 同一 DDL＋規則集，checking rule ID 結果必須一致。
3. 正式區不可捏造晉升；工具只搭骨架、不代填樣本或語意描述。
4. 每項完成即驗證，最後跑完整 regression（unittest ＋ golden ＋ lint）。
