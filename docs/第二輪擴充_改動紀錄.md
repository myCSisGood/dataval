# 第二輪擴充改動紀錄

> 對應計畫見 [第二輪擴充_計畫.md](第二輪擴充_計畫.md)。本檔記錄**實際做了什麼**、
> 動到哪些檔、如何驗證。九段全部完成，每段獨立可運作。

## 逐項改動

### 0. Advisory prompt 路徑 bug（`dataval/advisory_export.py`）
- 修正 prompt 內路徑 `config/advisory_result.schema.json` →
  `config/_engine/advisory_result.schema.json`。
- 把 `validate_advisory_result()` 實際檢查的規則（剛好三個 key、建議物件欄位剛好
  target/message/rationale 且非空、skill id 樣式）逐條內嵌進 prompt，agent 讀生成檔即自足。
- 在驗證函式上方標註「本函式／prompt 內嵌文字／schema 檔」三處耦合，改一處要同步。

### 1. 報告依 domain 分類（新增 `dataval/report_paths.py`）
- `primary_domain`（優先非 Common→Common→`_uncategorized`）、`report_dir_for`、
  `find_report_json`（先分類子夾、後扁平回退）。
- `run.py`：驗證回傳後、建報告路徑前先讀 `domains_loaded`，三式報告＋advisory_prompt＋
  subject_summary 落到 `reports/<域>/`；**precheck.md 維持扁平**。
- `merge_advisory.py`、`promote.py`、`tests/architecture_test.py`：改用 `find_report_json`
  定位既有報告；merge 輸出寫回報告所在資料夾。
- `.gitignore`：`reports/*.X` → `reports/**/*.X`，讓子夾的 html/prompt/summary 一併忽略；
  `.report.json`/`.report.md`/`.precheck.md` 仍入庫。移除被子夾取代的舊扁平報告。
- `README.md` 檔案地圖補分類規則說明。

### 2. Domain 腳手架（`rules.py`）
- 新增 `new-domain <NAME>`：建 `knowhow/{gating,advisory}/.gitkeep`、`naming/glossary.yaml`
  （三空 key）、`erd/<名>_core.mmd`（可解析最小 erDiagram）、`flows/_sample.flow.yaml`、
  `ssot/registry.yaml`；不覆蓋既有、印建立清單並提醒「規則仍需手動撰寫」。

### 3. 四件套骨架（新增 `scaffold_input.py`）
- `<名> <ddl_path>`：解析 DDL，產 `<名>.sql`（複製）、`samples/<表>.csv`（依型別佔位：
  int→1,2／string→sample_N／datetime→now／float→1.0／decimal→1.00／bool→true/false）、
  `relations.yaml`（有 FK→候選 N:1 標「務必確認」，否則 `relations: []`）、`context.md`
  （只填 subject 與「粒度」TODO 佔位）。
- 終端**明確警告**：樣本是假資料、基數未確認、粒度是佔位，跑 run.py 前都須人工替換。

### 4. Report diff（`dataval/report.py` ＋ 新增 `report_diff.py`）
- `diff_findings(old, new)`：以 `(check_id, target)` 為 key 回 `{added, removed, changed}`，
  changed 記 status/message 的 from→to，只讀 findings 故時間戳天生被忽略。
- `report_diff.py <舊> <新>`：載入兩份 JSON、印人讀摘要（新增／消失／改變逐筆）。

### 5. 正式區影響模擬（新增 `simulate_impact.py`）
- 重用 `prodgraph.load_subjects`，用現行磁碟 config 重跑每個正式區 subject（sample_data=None）；
  靠「晉升時零 fail」不變量：重跑後出現任何 blocking gating finding = 會由合規變不合規。
- 逐 subject 列出維持合規／新增 N 筆 fail，結尾統計；有退化回 exit 1。
- **揭露限制**：正式區不存樣本，樣本相依規則（型別對樣本、join key 編碼、基數實檢）
  測不到；結果是「至少會壞掉這些」。純只讀，不影響 promote/adopt。

### 6. Lineage 視覺化（`dataval/prodgraph.py` ＋ `frontend/index.html`）
- 後端 `export_graph(production_root, domains=None)`：重用 `load_subjects`＋`_edges`，
  回 `{nodes:[{id,domain,subject}], edges:[{from,to}]}`（資料方向：上游→下游）。
- 前端加「Lineage」分頁：零依賴 inline SVG，最長路徑分層佈局。單一 subject 圖純靜態
  即可用；全域正式區圖偵測到後端（`/api/lineage-graph`）才顯示，離線隱藏。

### 7. 顧問區文件整併（`AGENTS.md`）
- 「補完顧問區」段落註明：完整 JSON 格式與驗證規則已內嵌在生成的 `advisory_prompt.md`，
  照它做即可、不必另查 schema 檔；並更新 prompt/result 的分類子夾路徑。

### 8. 本機 Web 應用（新增 `webapp.py` ＋ `frontend/index.html`、`frontend/README.md`）
- `webapp.py`（`ThreadingHTTPServer`，零框架）：`GET /`、`GET /api/subjects`、
  `GET /api/subject?name=`、`GET /api/lineage-graph`、`POST /api/validate`。送驗把四件寫進
  `input/<名>/` 後**in-process 呼叫同一個 `validate()`**（不 shell 跑 run.py），走與 CLI
  相同的 precheck→validate 路徑；四件不齊回 `precheck_failed` 明細。
- 前端「送驗」分頁：名稱＋載入既有、DDL/samples/relations/context 編輯區，四件皆非空才
  啟用「送出驗證」；報告列出 fail/warning，「套用修正到編輯框」只插 `-- TODO(fix): …`
  到 DDL 對應表宣告附近（找不到插檔尾），**不自動送出、不改檔**。離線提示需先啟動 webapp。
- CLI（run.py/promote.py/rules.py）完全不受影響，可獨立使用。

### 9. Backlog（新增 `IMPROVEMENT_BACKLOG.md`）
- 記錄：四支入口腳本重複宣告路徑常數的技術債、advisory schema 雙權威來源、DataHub 必填
  欄位檢驗、scaffold FK 推測對 ClickHouse 空轉、前端全域圖佈局與零依賴取捨、測試補強、
  webapp 寫入 input/ 的取捨、模擬的樣本限制。
